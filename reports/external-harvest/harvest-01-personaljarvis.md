# Harvest 01 — PersonalJarvis

- **Project:** [PersonalJarvis/PersonalJarvis](https://github.com/PersonalJarvis/PersonalJarvis)
- **ID:** `harvest-01-personaljarvis`
- **Classification:** `PATTERN_ADOPTED`
- **GAIA action:** Adopt the concrete authority-boundary patterns below inside GAIA’s existing model; do not replace GAIA Core, its authority model, or its execution hosts. No PersonalJarvis code is copied.

## Verified license and uncertainty

The current `main` branch contains the [Apache License 2.0](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/LICENSE) and [NOTICE](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/NOTICE). The repository’s [licensing document](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/docs/licensing.md) states that `main` switched on 2026-08-27 and that version 2.0.0 is the first Apache-2.0 release; releases through 1.6.0 remain MIT. Apache 2.0 permits pattern study and code reuse subject to its notices, modification notices, license, NOTICE, and patent/trademark terms, but this harvest recommends **pattern adoption only**. Bundled components retain their own licenses (the NOTICE specifically calls out the Silero VAD model as MIT). **Uncertainty:** this verification covers the fetched current `main` files, not every historical tag or bundled dependency; any future code reuse needs file-level provenance and notice review.

## Concrete patterns GAIA can adopt

| GAIA authority area | Observed PersonalJarvis pattern | GAIA adoption (not replacement) |
|---|---|---|
| **Core** | An explicit layer model: higher layers call lower layers only through structural protocols; lateral communication is through typed events. Plugin contracts use `typing.Protocol` and entry-point registration. ([architecture](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/docs/architecture-overview.md), [protocols.py](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/jarvis/core/protocols.py)) | Add/strengthen protocol contracts at GAIA boundaries and reject direct cross-layer imports/calls where an authority boundary is intended. |
| **Permission Layer** | `RiskTierEvaluator` evaluates exact tool+arguments with precedence **blacklist > whitelist > tool default**, supports per-argument risk hooks, and fail-closes malformed tiers. Approval is for one exact call/trace, not a mission or future calls. ([risk_tier.py](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/jarvis/safety/risk_tier.py), [safety and approvals](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/docs/product/privacy-safety-and-support/safety-and-approvals.md)) | Add deterministic precedence, argument-sensitive classification, and single-call approval receipts to GAIA’s existing Permission Layer. Keep OS/service permissions separate from policy approval. |
| **Action Host** | `ToolExecutor` is the only authorized execution path: risk evaluation → plausibility check → approval → execution → events. Direct `Tool.execute()` is explicitly treated as a defect. ([tool_executor.py](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/jarvis/safety/tool_executor.py)) | Make GAIA’s Action Host the sole enforcement chokepoint and emit proposed/required/approved/denied/executed records for every action. |
| **Safe Mode** | Four decisions—`safe`, `monitor`, `ask`, `block`—separate low-friction execution, audit-only monitoring, human confirmation, and hard refusal. Fast paths still pass through the executor. This is a risk policy, **not** a universal sandbox or undo system. ([protocols.py](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/jarvis/core/protocols.py), [safety guide](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/docs/product/privacy-safety-and-support/safety-and-approvals.md)) | Use the four-way policy as a GAIA Safe Mode decision vocabulary and preserve the explicit limitation that it does not replace OS permissions, service scopes, sandboxing, or rollback. |
| **Kill Switch** | `CancelToken` + scoped `CancelScope` register only live operations; `KillSwitch` aggregates active tokens, listens for `KillRequested`, cancels all registered work, and emits per-holder acknowledgements. A separate Society kill switch persists state and cancels only Society-owned chats/missions/runs. ([cancel.py](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/jarvis/control/cancel.py), [runtime.py](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/jarvis/society/runtime.py)) | Add scoped cancellation, first-reason-wins semantics, bounded acknowledgement, and an authority-scoped emergency stop to GAIA. Do not infer that PersonalJarvis provides a universal rollback or that every process is stopped. |
| **RBAC** | No generic user/role RBAC model was verified. The concrete analogue is **mission-scoped capability grants**: short-lived broker grants, allowlisted tool names/server prefixes, fail-closed forbidden tools, revocation, TTL expiry, no connector credentials, and no direct tool handles. ([worker_tool_broker.py](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/jarvis/missions/workers/worker_tool_broker.py), [ADR-0031](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/docs/adr/0031-mission-scoped-tool-preauthorization.md)) | Adopt capability-scoped, TTL-bound grants in GAIA’s RBAC/authority adapter where needed; do not add a redundant role hierarchy or claim PersonalJarvis supplies one. |
| **Event Bus** | Immutable (`frozen=True`) event dataclasses carry `trace_id`, timestamp, and source metadata; typed and wildcard subscribers are supported; subscriber failures do not propagate, and wildcard observers have a timeout. ([events.py](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/jarvis/core/events.py), [bus.py](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/jarvis/core/bus.py)) | Adopt immutable, trace-correlated authority events, a flight-recorder/wildcard observer, and non-blocking observer isolation in GAIA’s Event Bus. |
| **Capability Router** | Router is deliberately a dispatcher, not a second action authority: explicit router-visible tools, verbatim user utterance forwarding, no recursive worker spawning, and worker calls mediated by the supervisor broker. ([router.py](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/jarvis/brain/router.py), [ADR-0011](https://raw.githubusercontent.com/PersonalJarvis/PersonalJarvis/main/docs/adr/0011-router-pure-dispatcher.md)) | Keep GAIA’s Capability Router selection-only; route execution and approval through GAIA Core/Permission Layer/Action Host, with explicit capability sets and recursion guards. |

## Decision boundaries

- **Adopt:** the patterns listed above because they make authority explicit, auditable, scoped, and fail-closed.
- **Do not reuse code in this harvest:** therefore `CODE_REUSED_WITH_LICENSE` is not selected.
- **No evidence-based rejection:** the inspected project is not rejected as redundant, insecure, over-complex, or license-incompatible; only the generic RBAC claim is not adopted because it was not present.
- **No replacement recommendation:** PersonalJarvis is a source of patterns for GAIA’s existing authority model, not an alternative architecture.
